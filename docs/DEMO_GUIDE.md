# Arus 管理员端：架构与比赛演示指南

**完整名称：** SME Receivables Risk & AI Collection Scheduler  
**中文名称：** 中小微企业应收账款风险预警与 ESG 加权 AI 智能催收排程系统

## 1. 运行与入口

启动已配置的 API Server 与 receivables-admin web 服务，在应用预览中打开 `/`。
工作台默认以明确标记的 Demo Admin 身份展示。`/login` 提供“进入演示”入口并记录登录日志。
这只是演示角色入口，不是生产身份认证；退出仅返回该入口，不构成访问权限撤销。
不同访问者共享同一个演示工作区，**请勿导入真实客户财务或个人资料**。

前端使用 Tailwind CSS、Recharts、TanStack Query。服务端使用 Express、Zod、Drizzle 和 PostgreSQL。
关键状态持久化在真实数据库中，不是浏览器内存或假保存。

### 数据模型与存储

十种领域实体：Invoice、Customer、ESGDocument、RiskEvent、CollectionPlan、CollectionTask、
ApprovalRecord、ExecutionRecord、AuditLog、SystemSetting。
发票关联客户；凭证关联客户；方案关联风险事件与方案家族；任务关联发票与客户；
审批保留原始/最终快照；执行记录关联方案和任务；日志保留关联对象、前后状态和方案版本。

MVP 将这些类型化实体集合保存在单个 PostgreSQL JSONB 工作区聚合中，并非十张规范化关系表。
采用该方式是为了让业务修改、版本保留和审计追加处于同一事务。行锁保证不同标签页审批/执行不会并发重复。
后续可以替换 repository 层、拆分关系表；当前不适合作为生产级大规模会计系统。

金额以 MYR 的整数分存储；关键金额乘法和四舍五入采用 BigInt。浮点数只用于非金融余额的优先级分数和界面显示。
罚息率以基点保存：1200 = 年利率 12%，并非每日 12%。

## 3. Demo 数据说明

- 10 个虚构马来西亚企业客户，行业、业务重要度及付款背景均为合成。
- 26 张发票：20 笔未收清（含 4 笔部分收款）、4 笔已收款、2 笔已取消。
- 初始时 8 笔未收清发票已逾期；未来 7 天内另有 8 笔到期。
- 8 份模拟 ESG 审核记录，覆盖 ISO 14001、ISO 45001、MSPO、MyHIJAU，以及通过、待审核、驳回、过期、待补充资料。

- 首次自动生成一个高风险事件和一个待审批方案，方便直接查看完整页面；也可从风险检测开始新流程。
- 发票日期相对于初始化/重置当天生成；应用日期采用马来西亚时间，状态随当前日期重新计算。

## 4. 风险规则

预计现金 = 当前现金 + 检测期内尚未逾期的到期未收余额 × 预计收款率 − 检测期预计支出。
已逾期账款单独作为风险敞口展示，不默认假设能在检测期内收回。

1. 预计现金低于运营最低需求：**High**。
2. 预计现金介于最低需求与其缓冲线上限之间（含边界）：至少 **Medium**。
3. 到期集中笔数达到阈值：至少 **Medium**。
4. 逾期未收总额达到阈值：至少 **Medium**。
5. 任一逾期账单金额达到大额阈值：至少 **Medium**。
6. 无上述触发条件：**Low**。

所有参数均在 Settings 修改。工作台读数据时自动计算当前风险；
Run Risk Check 会另外追加一个带参数快照的历史事件，重复运行会产生新的事件。
30 天图中的预计现金只是规则示意：支出按检测期天数摊分，超过该检测期不再额外假设支出。
该图并非完整预算或经过统计验证的收款预测；没有可信置信区间可展示。

## 5. 四维评分

默认权重：罚息 30%、紧急度 35%、重要度 25%、ESG 10%，合计必须为整数 100%。

- **罚息得分**：先以简单年利率计算预估累计罚息和日罚息（整数分）。
  得分 = min(100, 累计罚息分 / 1000 + 日罚息分 / 50)。
  罚息仅作解释，不会计入账单余额或产生真实收费。
- **紧急度**：逾期时基础分为 65 + 逾期天数；未逾期时为 max(0, 60 − 距到期天数 × 3)；
  再加 min(20, 未收金额分 / 500000)，最终封顶 100。
- **重要度**：High 为 25，Medium 为 55，Low 为 80，用于对重要客户采取更温和的关系维护安排。
- **ESG**：只使用模拟审核通过且有效的评级；A = 30，B = 50，C = 70，未认证/无有效证据 = 中性 50。
- 综合分 = 各项分数 × 对应百分比之和 / 100；同分时按到期日、发票编号稳定排序。

这不是坏账概率、信用评级或真实业务验证后的最优算法。每笔任务展示因素得分、权重、理由、
沟通建议、协商说明、数据缺失和不确定性。ESG 不覆盖合同到期义务。

## 6. 八步端到端演示

1. 打开 Dashboard，说明合成数据标识、现金余额、待收余额和高风险原因。
2. 进入 Risk Triggers，点击 **Run Risk Check**，查看新记录和触发规则。
3. 点击新事件的 **Generate plan**，进入该方案的审批页面；也可进入 AI Collection Planner 修改权重再生成。
4. 展开任务，查看四项分数、原因和英文/马来文模板。未认证客户显示中性 ESG 分数。
5. 在 Approval Center 用上下箭头调整顺序，修改方式/双语通知或备注，点击 **Save edits as new version**。
   新版本为 Pending，旧版本变为 Superseded；修改未保存前不会允许批准。
6. 点击 **Approve & Simulate Execution** 并确认。此按钮完成审批，**并不立即模拟发送**；
   确认框会明确说明还需在执行页单独操作。方案状态更新为 Approved。
7. 进入 Execution Results，选择批准方案，点击 **Execute Approved Plan** 并确认。
   每笔任务生成模拟执行记录；余额和付款状态不变。点击 **Export Report** 下载 CSV。
8. 进入 Audit Logs，按类型、时间、操作人、客户或发票筛选，查看风险、生成、调整、审批和模拟执行的前后快照。

刷新页面后，关键数据、版本、审批和执行记录仍在 PostgreSQL 中。
未审批的方案不能执行；重复执行同一已执行方案不重复创建任务记录。
修改现金参数、导入发票或跨日后，旧方案可能失效；服务端会提示先 **Defer & Recalculate**。

## 7. 七个演示情景

### A. 现金充足、风险低

在 Settings 设置：
- 可用现金 MYR 500,000
- 逾期金额阈值 MYR 1,000,000
- 大额账单阈值 MYR 1,000,000
- 到期集中笔数 100
- 其余保持初始值

保存并运行风险检测，预期为 Low。这也说明现金充足并不代表逾期/集中规则自动失效：
需要同时无其他触发条件才是低风险。

### B. 集中到期使风险升高

承接 A，仅将集中到期笔数改回 5，保存并检测，预期为 Medium。

### C. 大额逾期与罚息影响

确认重置 Demo 数据，恢复初始高风险场景。在排程中查看最高优先级大额逾期发票的年度罚息、
日预估成本和累计预估成本，解释其评分因素。

### D. ESG 缺失正常排程

在 Customers 中筛选 Uncertified，选择没有有效审核文件的客户。在排程中找到其任务，ESG 得分应为 50，
说明没有基于缺失文件推断欺诈、违约或坏账。

### E. 人工调整并批准

按第 6 节步骤修改任务顺序、模板或方式，保存新版本，再批准。审计记录保留原始和修改版本。

### F. 延后重新排程

对 Pending 方案点击 Defer & Recalculate，确认后旧版本为 Deferred，新版本为 Pending；
使用最新数据和 Settings 中保存的权重重算，并将建议沟通时间延后两个演示日。
如想修改权重后重排，先保存 Settings，再延后重排。

### G. 审批后模拟执行

批准新版本，进入执行页模拟执行，再导出报告并在审计中心查看逐任务和整方案记录。
重置 Demo 需要确认，不删除已有审计、审批或执行历史。

## 8. CSV 导入与导出

在 Receivables 下载 CSV template，可使用虚构数据修改后上传。

必需字段：

```csv
invoice_number,customer_name,invoice_date,due_date,total_amount
DEMO-IMPORT-001,Example Synthetic Trading,2026-10-01,2026-10-31,12000.00
```

也可用 invoice_id 代替 invoice_number。
可选字段：amount_paid、outstanding_amount、currency、late_fee_rate、business_importance、
payment_status、industry、esg_rating。

- currency 只能是 MYR；其他币种整批拒绝，必须先转换或排除，不会跨币种相加。
- late_fee_rate 为年百分比，例如 12.00；金额最多两位小数，日期必须是有效 YYYY-MM-DD。
- 缺失 amount_paid 但有 outstanding_amount 时按差额推导；两者均缺失时演示规则估算已付为 0，并标记估算。
- 缺失 outstanding_amount 时按总额减已付计算；缺失罚息率估算为年 12%，同样标记。
- 重要度 High / Medium / Low；缺失时为 Medium，不推断真实客户关系。
- 状态值 Upcoming / Due soon / Overdue / Partial / Paid / Cancelled。
  除取消外，实际显示状态由金额和日期重新计算；Paid 必须已付全额。
- 上传的 ESG 评级没有独立审核证据，不会被当作有效评级使用。
- 无效行、重复发票、付款超过总额、余额矛盾、无效日期等均明确报错；验证失败不部分导入。
- 导入记录保留文件名、时间和估算字段。现有客户按名称匹配，不覆盖其业务重要度。
- 当前筛选结果和批准排程报告均可导出 CSV；金额列标明 MYR，CSV 字符串防范公式注入。

## 9. 仍为模拟或尚未实现的边界

| 项目 | 当前状态 |
|---|---|
| 规则引擎、风险计算、CSV 校验、持久化、版本与审批门禁 | 真实运行的应用逻辑 |
| 通知内容 | EN/MS 预设模板，可人工编辑；不是 LLM 输出 |
| Gemini | 仅预留服务端顾问接口，尚未连接、未校验真实 API 凭据；选择该模式会明确报错，不会静默假装启用 |
| 执行、邮件、短信、付款 | 仅 Demo 模拟；不真实发送、不扣款、不转账、不改变已收金额 |
| Demo 登录 | 无生产身份认证、权限隔离或多租户能力 |
| ESG 文件 | 明确标记的模拟审核文本，不提供伪造官方证书、不具备真实认证效力 |
| ESG 审核操作、客户端、认证员端 | 不在本次范围 |
| 生产能力 | 未实现正式身份认证、真实文件管理、经验证的财务/信用模型、通知送达回执、生产安全合规或大规模规范化存储 |
