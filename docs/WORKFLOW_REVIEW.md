## B. 关键代码与实际测试

### 1. 风险与触发

- `artifacts/api-server/src/lib/receivables/compute.ts`：现金预测与 R1–R5。
- `artifacts/api-server/src/lib/receivables/service.ts`：记录检测、启动待审批方案、数据签名校验。
- `artifacts/receivables-admin/src/pages/risk-triggers.tsx`：真实检测请求、展示与方案入口。
- R1：预计现金低于最低线为 High；相等不为 High。
- R2：缓冲上限含边界为 Medium；高一分且无其他触发为 Low。
- R3：使用逾期未收余额（含部分付款），达到阈值触发。
- R4：今天到期、检测期末到期均计入；已经逾期、超期一天均不计入集中度。
- R5：达到大额阈值且已经逾期才触发；未来大额账单不触发该规则。
- 手动 High 检测产生 Pending 方案但不执行；Low 记录事件且不自动催收。
- 历史事件与当前数据不同，创建新的当前事件；延期也重新检测，旧事件不变。
- 无定时器/调度器：这是代码审查结论，不是“定时任务测试通过”。

### 2. 同源数据

- `model.ts`：整数分、基点年利率、马来西亚日期。
- `compute.ts`：从未收金额和日期计算状态、KPI、风险；有效 ESG 与重要度取客户/凭证集合。
- `repository.ts`：真实 PostgreSQL JSONB 工作区及行锁事务，不是 UI 临时状态。
- 测试改变测试副本的现金、到期日、已收金额、罚息率和重要度，断言计算随之改变。
- 已收清/取消账单排除；逾期余额不假定在预测期内收回。
- 仪表盘余额与同模型账单求和一致；方案任务对应可催收账单。
- API 测试前后逐对象比较客户、账单、设置和 ESG，全部不变。

### 3. 评分与建议

- `planner.ts`：四个分数、加权综合分、稳定排序、建议方式和理由。
- `communication.ts`：付款、分期、短延期三套协商备选；只将首选写入 EN/MS 草稿，需人工及客户同意。
- `ai-provider.ts`：实际规则顾问；未连接 Gemini 接口明确报错，不假装调用模型。
- 测试逐任务重算加权和；四个维度分别 100% 权重时总分等于该维度。
- 非 100% 权重拒绝。年罚息率或重要度变化实际影响得分。
- 有效已通过 A/B/C 对应 30/50/70；无凭证、Pending、驳回、过期、待补充均 50。
- 不把 ESG 缺失当坏账证据。ESG 只是辅助排程，不提供经验证的坏账概率。
- 当前可验证的是未接入 AI 时明确采用规则和模板；未验证任何外部模型响应、凭据、限流或故障恢复。

### 4. 审批

- `service.ts` 的 edit/decide/assertFresh，前端 `pages/approvals.tsx`。
- 顺序及双语修改保存为新版本，原任务保持不变，原版 Superseded。
- 改方式时未人工改动的模板随新方式更新；自定义双语保留，并显示核对提示。
- 延期保留家族、升版本、重新检测和排程，新版仍 Pending。
- 拒绝、未批准、旧版不可执行；数据/设置/ESG变化后不可批准或执行陈旧方案。
- 批准快照包含 originalSnapshot/finalSnapshot；批准本身不产生执行结果。
- Demo Admin 是固定演示角色；没有按真实身份确认审批人的测试条件。

### 5. 执行与审计

- `service.ts` 的 execute/audit/documentView；`repository.ts` 事务；`routes/receivables.ts` 输入输出验证。
- 前端 `pages/execution-results.tsx`、`pages/audit-logs.tsx`、`pages/esg-documents.tsx`。
- API 对同一批准版本并发请求两次执行，只产生一组逐任务执行记录。
- API 非法编辑返回 400 且方案数/日志数不变，证明没有部分提交该修改。
- 未审批执行返回 409；拒绝后和旧版执行均返回 409。
- 执行前后财务、客户、设置、凭证数据完全一致；代码中无真实邮件/扣款/转账服务调用。
- 完整建议与四维输出保存在生成方案日志 after；人工改动有 before/after；审批有快照；执行逐任务有记录。
- ESG 查看日志现在保留模拟记录、结论、理由、有效期及来源快照，**不是**管理员审核或真实认证员历史。
- 审计是应用层追加记录，不是第三方不可篡改账本；数据库管理员仍能修改数据。

## D. 浏览器手动完整演示

1. 打开 `/`，确认 Synthetic demo 标记；记录现金、应收余额与逾期余额。
2. `/risk-triggers` → **Run Risk Check**。默认数据为 High，生成新检测和 Pending 方案。
3. 点击该结果的 **Generate AI Collection Plan**，打开该事件的同一待审批方案（去重），而不是另造重复方案。
4. 展开任务：查看四维分、权重、综合分、排序、原因、三套协商策略、ESG中性提示，以及 EN/MS。
5. 改顺序、方式和两种语言话术 → **Save edits as new version**；确认版本递增、旧版 Superseded。刷新确认保存。
6. **Defer & Recalculate** → Confirm；确认新风险事件、新 Pending 版本、重排时间。可对此版 **Reject Plan**，证明拒绝不能执行。
7. 回到风险中心再运行一轮，打开本轮 Pending 方案 → **Approve & Simulate Execution** → Confirm。此时仅 Approved，还未执行。
8. `/execution-results` 选择刚批准的准确版本 → **Execute Approved Plan** → Execute；查看逐任务模拟结果与草稿，刷新仍存在，不会重复执行。
9. `/esg-documents` 查看模拟凭证记录，确认不是官方证书且没有管理员审核按钮；关闭。
10. `/audit-logs` 查看本轮风险、生成、人工修改、审批、模拟执行及 ESG 查看条目，打开 before/after。
11. 返回工作台/应收表，确认现金及账单已收金额没有被模拟执行更改。

不要通过 Reset 清除测试历史；本轮保留这些历史作为可追溯验证证据。
